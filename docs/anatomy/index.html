Anatomy of a UDeep file

A UDeep figure is an ordinary image file with one thing added: a declaration of how its data became the picture, stored where the image format keeps metadata (profile 8.8). Below, the two valid conformance files are taken apart as they are. Both show the same synthetic data, a ramp with one bright spot, 40 by 60 values; the page is made from the files, so it shows what they hold.

A gain-map JPEG

valid.jpg, 5,009 bytes: two JPEG images in one file. The first is the ordinary figure, which any program shows. The second, after it, is the gain map, which a screen that can show HDR uses to make the bright parts brighter than white. The declaration is in the first image's XMP segment, beside the gain map's own description.

the declaration's segmentother metadataimage data

In a figure this small (60 by 40 pixels) the metadata is a large share of the file. In the 18 HDR figures of this site's gallery, the declaration is 1.5 to 1.7 KiB of files from 184 KiB to 1 MiB, under 1 % of each.

Where it must be, and what a reader does

  • One declaration a file, in one XMP packet. A reader takes it only from the place below, and refuses a file that holds two.
  • In a gain-map JPEG, the primary image's XMP segment (APP1), never the gain-map image's. One segment holds at most 65,533 bytes; this declaration is 1,757 bytes with its packet.
  • In a PNG, an iTXt chunk named XML:com.adobe.xmp, not compressed, before the image data. In an SVG, the <metadata> element.
  • Properties are written as attributes; a reader also takes them written as elements, as other XMP tools may rewrite them.
  • A signature, when there is one, is added after the declaration, so that it covers it.

The conformance files break these rules one at a time, with the verdict a validator must give.
